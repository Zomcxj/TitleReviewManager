# 功能说明

## 完整功能列表

### 用户与认证
- 用户登录/登出
- JWT Token 认证（HTTP-only Cookie）
- 基于角色的访问控制（RBAC：管理员/业务员/审核员）
- 密码 bcrypt 加密存储
- 登录限流与账号锁定（阈值与时长由系统配置驱动，默认 10 次失败锁定 15 分钟；登录成功/失败/锁定均记入审计日志）
- 用户管理（管理员：创建/编辑/删除用户）
- 自助修改密码

### 客户管理
- 客户信息 CRUD（含拼音首字母自动填充）
- 客户列表搜索/筛选（关键词、状态、分页）
- 客户详情页（基本信息、项目经历、所有申报批次）
- 客户分配（业务员）
- 批量分配客户
- NAS 目录自动创建（按年/业务员/客户）

### 申请管理
- 申请表单填写
- 状态机流转（6 种状态，严格约束）
- 申请材料上传/删除/版本管理
- 申请状态跟踪
- 二次申报（基于不通过批次重新申报）

### 材料管理
- NAS 目录模板存储：`{year}/{salesman}/{customer}_{pinyin}/{category_number}-{category_name}/{filename}`
- 保留原始文件名，同名自动加后缀
- 按类别分组，版本管理
- 文件预览（图片内联 / PDF 新标签页）
- 文件目录树浏览（NAS 视角）
- 关键词/类别/审核状态筛选
- 文件操作审计日志
- 上传限流（50MB，白名单扩展名）

### 存储架构
- 存储后端抽象层（Storage Abstraction Layer）
- 支持本地文件系统或 SMB NAS
- 目录模板可配置（`customer_dir()` 函数）
- 拼音首字母自动计算（GB2312 编码区间映射，无需 pypinyin）
- 文件审计日志（`file_audit.log`）

### 审核工作台
- 待审核材料列表
- 单份/批量审核
- 审核通过/退回（含问题类型标注）
- 审核意见填写
- 修订稿上传

### 通知中心
- 系统通知列表
- 未读消息提醒铃铛
- 自动通知（状态变更、审核分配等）
- 通知标记已读

### 跟进记录
- 添加跟进记录
- 跟进时间轴展示
- 最后跟进时间追踪

### 公海池管理
- 公海池客户列表（关键词筛选）
- 领取公海客户（持有上限由系统配置 `pool_claim_limit` 控制，默认 50）
- 释放客户到公海
- 公海池统计（总数、今日领取、超时、即将超时）
- SLA 定时器：`pool_recovery_days`（默认 7 天）无跟进自动回收；分配后按 `sla_hours_after_assign`（默认 24h）计算 SLA，超时通知后清除截止时间避免重复轰炸

### 审计日志
- 操作记录查询
- 按用户/操作类型/资源筛选
- 管理员专属功能

### 批量导入/导出
- Excel 批量导入客户（xlsx/xls）
- 支持客户列表导出 Excel
- 支持申报批次导出 Excel
- 导入结果展示（成功数/失败详情）

### 数据看板
- 统计卡片（客户总数、申请总数、今日/本周新增）
- 申请状态分布图
- 业务员业绩排名
- 趋势分析（按日期统计申请量）

### 材料清单与提交校验
- 按专业类别自动生成必传材料清单（`enums.required_materials_for()`）
  - 通用必传：身份证明、学历学位、聘用/劳动合同
  - 按专业关键词追加：职称证书 + 业绩成果 / 论文著作 / 继续教育
- 批次材料完备性查询接口（缺哪些类别一目了然）
- **提交评审机构前强制校验**：缺料直接拒绝并列出缺失类别，杜绝空批次报送

### 客户进度自助查询（公开页 `/progress`）
- 无需登录，客户自行查询申报进度
- 双重校验：完整身份证号 + 手机号后 4 位（避免仅凭身份证号枚举）
- IP 限流（5 分钟 20 次）
- 展示进度时间线、材料统计、最近机构反馈
- **不返回**身份证号、手机号、工作单位等敏感字段

### 收费/合同/回款与证书跟踪
- 合同编号、签订日期、合同金额
- 回款登记（可多次），自动汇总已收金额与收费状态（未收费/部分收费/已结清/已退款）
- 待收款提醒（按欠款额倒序）
- 财务总览（管理员）：总合同额/已收/未收、按业务员汇总、收费状态分布
- 证书跟踪：证书状态（未发证/已发证/已交付）、证书编号、发证日期、交付日期

### 系统配置（管理员）
- 在线调整运行参数，保存后立即生效（无需改代码重启）
- 可配置项：公海持有上限、无跟进回收天数、分配后 SLA、待审核 SLA、单文件大小上限、登录失败锁定阈值与时长、是否拒绝重复手机号
- 支持一键恢复默认值

### 回收站（管理员）
- 客户/申报批次/用户的软删除，误删可恢复
- 恢复时校验唯一性（如身份证号冲突则拒绝）
- 彻底删除（物理删除）带依赖校验：客户有批次、用户有客户时拒绝
- 删除保护：存在评审中批次（已提交/返修/通过/不通过）的客户不可删除

### 数据质量
- 身份证号查重（全部录入入口）
- 手机号查重（可选开关，默认仅提示不拦截）
- 客户来源渠道记录（转介绍/网络/线下/合作机构/自助注册）
- 申报年度（`cycle_year`）自动记录

### 审计增强
- 登录成功/失败/锁定拒绝均记入审计日志（含 IP、User-Agent）
- 材料下载留痕（PII 合规：记录下载人与文件名）

### 外部通知渠道（可选）
- 站内通知始终生效；配置后可额外推送到外部渠道，用户不登录也能收到提醒
- **邮件通知**：SMTP 配置（支持 SSL / STARTTLS / 无认证内网中继）
- **Webhook 通知**：兼容企业微信/钉钉/飞书机器人（POST JSON）
- 按通知类型过滤（默认只推 status_change / sla_overdue / pool_recovery，可配置为全部）
- 异步发送（后台线程），未配置时静默跳过，发送失败不影响业务
- 管理员可在用户管理中维护收件邮箱

### 数据一致性
- **SQLite 外键约束**：通过 PRAGMA foreign_keys=ON 在每个连接启用，行为与 PostgreSQL 对齐，避免悬挂引用

### 大数据量导出
- 导出改用 openpyxl write_only 模式 + SQLAlchemy yield_per 流式游标 + StreamingResponse
- 实测 2 万行导出内存峰值从 160.7 MiB 降至 17.1 MiB（约 9.4 倍）
- 导出上限保护（客户/批次 5 万行、审计 1 万行），超出追加截断提示
- 临时文件用 BackgroundTask 兜底清理，异常/中断场景不残留

### 材料在线预览
- 图片内联、PDF 内嵌、**docx 本地解析预览**（mammoth → HTML + DOMPurify 净化）
- 敏感材料全程不出本域，不使用任何第三方在线预览服务
- .doc 旧二进制格式不支持解析，引导下载

### 安全加固
- **安全响应头**：CSP（frame-ancestors 'none' 防点击劫持）、X-Frame-Options DENY、
  X-Content-Type-Options nosniff、Referrer-Policy、Permissions-Policy；
  生产启用 HTTPS 时可开 HSTS（`ENABLE_HSTS=1`）
- **Token 撤销机制**：用户表带 `token_version`，改密 / 管理员重置密码 / 删除用户时自增，
  已签发的旧 token **立即失效**（此前改密后旧 token 仍可用满 8 小时）；
  每个请求回查数据库校验账号存在性、软删除状态与角色，token 中的旧角色不再被信任
- **上传内容校验（魔数）**：除扩展名白名单外，校验真实文件头
  （PDF `%PDF`、PNG/JPEG magic、OOXML `PK`、OLE 复合文档），
  拦截把 HTML/脚本改名为 .pdf/.png 上传
- **文件名安全**：去掉路径信息、阻断 `../` 与绝对路径穿越、限制长度，
  落盘与入库统一使用净化后的名称（此前入库保留原始文件名）
- **路径越界防护**：文件读取/删除前校验相对路径未越出存储根目录
- **暴力破解告警**：同一 IP 10 分钟内登录失败 ≥20 次时通知全部管理员，
  30 分钟内同一 IP 去重避免轰炸
- 密码强度校验：拒绝常见弱口令、纯数字、纯字母，长度 ≥8
- **导出安全**：导出含证件号的客户名单时可选脱敏（`?mask=true`，
  身份证 `110101********0015`、手机号 `138****8001`）；
  **所有导出操作记入审计日志**（谁、何时、导了什么、是否脱敏）——
  此前导出无任何留痕，是资料外流的主要盲区
- **字段级权限（敏感字段脱敏）**：客户身份证号与手机号按角色与归属自动脱敏
  - 管理员：完整
  - 业务员：仅自己名下客户完整（日常核对需要），他人客户脱敏
  - 审核员：一律脱敏（审核材料不需要完整证件号）
  - 公海池客户：除管理员外一律脱敏（避免批量抓取）
- **批量操作防护**：单次上限 200 条（超限提示分批）、自动去重（避免重复通知）、
  频率限制（每用户 10 分钟 20 次）—— 此前无任何限制，一次传上万 ID 可刷出上万条通知
- **前端错误上报**：Vue 渲染错误、全局 JS 异常、未处理 Promise 拒绝、接口 5xx
  自动上报到后端（匿名可用，登录页出错也能记录）；管理员可在「前端错误」页
  查看真实堆栈与发生频次，不再依赖用户口头描述
  - 防循环：上报走原生 fetch 不经过 axios 拦截器，catch 内不 console.error
  - 防轰炸：同一错误 60 秒内只上报一次
- **登录设备管理**：每次登录记录一条会话（`user_sessions` 表），token 携带 session_id
  - 可查看自己所有活跃设备（设备描述由 UA 解析：Chrome / Windows、Safari / iPhone 等）、
    IP、登录时间、最后活动时间
  - 支持**单设备下线**（手机丢失只踢手机）与**下线其他所有设备**（怀疑被盗时一键处理）
  - 修改密码时保留当前设备、其余全部失效；退出登录会撤销当前会话（而非仅清 cookie）
  - 过期会话由调度器定期清理（默认保留 30 天）
- **审计日志防篡改（哈希链）**：每条日志带 `prev_hash` + `entry_hash`（SHA-256），
  改动任意一条或删除中间记录都会导致链断裂；`GET /api/audit/verify-chain` 可校验并定位异常记录，
  审计日志页提供「校验完整性」按钮。局限性：删除末尾记录无法检测（需外部锚定链尾哈希），
  且攻击者若能重算整条链仍可伪造 —— 价值在于把"静默篡改"变为"必须重算全链"

### 跟进日程与提醒
- `GET /api/follow-ups/schedule?scope=today|overdue|week` 待跟进日程
  （每个客户取其**最新一条**跟进记录的 `next_follow_up_at` 作为当前待办）
- `GET /api/follow-ups/summary` 待跟进汇总（逾期/今天/本周）
- 逾期自动提醒：调度器定期检查，向业务员推送「跟进已逾期」通知，
  **同一客户每天只提醒一次**（避免轰炸）
- 业务员仅见自己名下客户；侧栏菜单带逾期数量角标

### 材料退回原因统计
- `GET /api/dashboard/rejection-stats?days=90`
- 维度：按材料类别（哪类材料最常被退回）、按问题类型、按业务员对比、近 30 天趋势
- 用途：反推预防措施（如"业绩成果"退回率最高则上传前重点检查）、评估业务员材料质量
- 业务员仅统计自己名下客户

### 转化漏斗
- `GET /api/dashboard/funnel?days=180`
- 四阶段：建档 → 材料准备（有材料上传）→ 提交机构 → 评审通过
- 每阶段给出相对上一阶段与相对起点的转化率，并标出**流失最多的环节**
- 业务员仅统计自己名下客户

### 批量材料下载
- `GET /api/applications/{id}/materials/download-zip?category=xxx`
- 打包为 zip（zip 内保留类别目录便于解压归类），只含每类别的**最新版本**
- 单次打包上限 300MB（超出提示按类别分批）
- 文件缺失时在 zip 内附「_缺失文件说明.txt」
- **下载记入审计日志**（材料含客户证件影像）

### 今日待办工作台
- `GET /api/dashboard/workbench`：按角色汇总四类待办（跟进 / 内部审核 / 申报截止 / 待收款）
  - 业务员：只看名下客户的跟进逾期、审核积压、申报截止、待收款
  - 审核员：看全部待审批次，不展示财务数据
  - 管理员：全部可见
- 仪表盘顶部新增「今日待办」卡片：5 个指标 + 跟进/审核积压/申报截止三列明细，点条目跳转处理
- 数据实时联动（审核一份材料后，队列与指标即时减少）

### 内部审核 SLA
- `applications.review_sla_deadline`：批次进入「完成资料」时按系统配置
  `sla_hours_before_review`（默认 48h）自动写入截止时间；离开待审状态
  （提交机构 / 批量通过 / 状态回退）时自动清空
- `GET /api/reviews/pending`：真实待审队列（只含仍有待审核材料的批次，
  按 SLA 截止升序，超时批次红底标识、显示剩余/超时小时数）
  - 此前审核台在前端硬筛客户列表，会漏掉有积压材料但状态不符的批次
- 超时催办：调度器每轮检查超时批次，通知分配审核员（未分配则通知全部审核员）+ 管理员，
  已全部审完的批次不再催；同一对象每天只提醒一次

### 申报截止催办
- 调度器每轮检查 `cycle_deadline`：已逾期或 3 天内到期（未到终态）的批次，
  通知归属业务员 + 管理员；逾期与临期分两种通知类型，同批次每天最多提醒一次
- 跟进逾期提醒接入调度器（此前 `send_overdue_follow_up_reminders` 已实现但无人调用）

### 使用教程（站内帮助）
- 侧边栏「使用教程」入口（全角色可见），打开时自动定位当前角色分组
- 按角色分 tab：通用（5）/ 业务员（11）/ 审核员（5）/ 管理员（11），共 32 个功能卡片
- 每卡：入口路径 + 说明 + 分步操作（按钮级）+ 小贴士；顶部搜索全文过滤
- 内容与系统实际参数对齐（SLA 48h、公海上限 50、锁定 10 次等）

### 部署
- Docker 容器化（`docker-compose.yml`）
- 支持 SQLite（开发）/ PostgreSQL（生产）
- **启动时轻量 schema 同步**：自动补齐缺失的表与列（只加不删），已有库升级代码后可直接启动
- 前端 Vite 热更新 / 生产构建
- CORS 白名单配置
- 全局异常处理
